b# Milestone M2.1: Track Timeline Editor

## Goal

Turn the Recording Studio timeline into a DAW-style editor surface for selecting
tracks, clips, and time spans before later redaction or editing work adds
durable manipulation metadata.

## Summary

- M2.1 is a UI and state-architecture milestone for timeline editing.
- The captured MKV files remain immutable ground truth.
- Track order, labels, colors, clip titles, and selections are session-local in
  this milestone.
- Redact and Cut actions are visible placeholders only. They must not mutate
  files, SQLite rows, processing state, or derived data.

## Locked Decisions

- The editor state lives in a session-scoped Zustand store keyed by recording id.
- The UI renders one clip box per existing recording segment per lane.
- Future cut, redaction, stitch, and reorder behavior must be represented as a
  manipulation layer over source media, not by splitting or rewriting MKV files.
- Click seeks; dragging past a small threshold selects.
- Time ruler drag selects the chosen time range across all visible lanes.
- Lane-content drag selects only lanes intersected by the marquee.
- Selection is one mixed model containing selected lanes, clips, and time ranges.
- Default lane colors rotate through a fixed 24-color palette.
- Color and label edits are draft UI state only in M2.1.
- Lane sorting uses dnd-kit for pointer and keyboard-accessible reordering.
- Placeholder Redact and Cut buttons appear in both the timeline toolbar and the
  sidebar actions section when a time range exists.

## Success Criteria

- The timeline has separate ruler, lane list, lane caption/header, clip box,
  selection overlay, toolbar, and sortable wrapper responsibilities.
- StudioSidebar shows a scrollable inspector with generic selection details,
  selected-kind details, editable labels/colors, and bottom actions.
- Selecting a lane or clip highlights the corresponding timeline item and
  updates StudioSidebar.
- Ruler and lane drag selection produce visible time-span overlays.
- Lane sorting changes the visible order without breaking playback, mute,
  waveform, or thumbnail behavior.
- The UI remains responsive at one desktop and one narrow viewport.

## Scope

In scope:

- Timeline editor Zustand store.
- TrackTimeline hierarchy refactor.
- DAW-style selection gestures.
- Session-local rename and color assignment.
- 24-color palette.
- dnd-kit lane reordering.
- Sidebar inspector redesign.
- Focused unit and browser tests.

Out of scope:

- Persisting lane order, labels, colors, clips, or selected ranges.
- Creating database migrations or Tauri commands.
- Cutting, redacting, stitching, or rewriting media.
- Deleting or invalidating derived processing data.
- Adding new track kinds beyond current video and audio tracks.

## Risks and Edge Cases

- Drag gestures must not accidentally break click-to-seek.
- Pointer selection, scrollbar use, mute buttons, and drag handles must not
  fight for the same event targets.
- Browser tests must assert visible UI behavior, not only internal store state.
- Session-local draft edits may look persistent; the UI should not imply they
  are saved permanently.

## Assumptions

- Current track kinds are video, desktop audio, and microphone.
- Persistence is a later gate.
- Redaction deletion/invalidation semantics stay owned by later redaction work.
